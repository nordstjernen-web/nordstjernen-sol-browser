web-text-lib
============

Nordstjernen's text layout library: a specialized library to render text for a web browser.

The top-level `meson.build` loads this directory with
`subdir('src/web-text-lib')` (the same pattern as `src/quickjs` and
`src/wamr`). It builds static libraries and exposes three dependencies:
`web_text_dep` (the core layout library), `web_text_cairo_dep` (cairo
rendering) and `web_text_fc_dep` (fontconfig/FreeType fonts). No clone or
network access is needed, so offline and distro builds get it straight from
the source tarball. It needs GLib >= 2.80, cairo >= 1.18 with FreeType and
fontconfig, HarfBuzz >= 8.3, FriBiDi >= 1.0.6 and fontconfig >= 2.15. `-Dweb-text-lib=disabled` skips it and links the system
Pango instead, which Android and iOS always do; the engine then compiles
with `NS_USE_WEB_TEXT_LIB` undefined. The sources sit directly in
`src/web-text-lib/` and are included as `<web-text-lib/...>`; the engine reaches them only through
`src/ns_pango.h`. The modifications stay under upstream Pango's LGPL
terms; see `COPYING`.

The library is trimmed to what the browser calls. Every function that no
path from the engine reaches was removed, together with the files left
empty (markup parsing, colour parsing, the engine/module registry, the
reorder and trace helpers) and the generated enum GTypes, of which only
`NsPangoGravity`'s is used and is now written out in `pango-gravity.c`.
A new caller in the engine may therefore need a function restored from
upstream Pango (renamed with `ns-rename.py`).

Dependencies
------------
Pango depends on the GLib library; more information about GLib can
be found at https://www.gtk.org/.

To use the Free Software stack backend, Pango depends on the following
libraries:

- [FontConfig](https://www.fontconfig.org) for font discovery,
- [FreeType](https://www.freetype.org) for font access,
- [HarfBuzz](http://www.harfbuzz.org) for complex text shaping
- [fribidi](http://fribidi.org) for bidirectional text handling
  

Five things differ from upstream.

**A cross-layout shaping cache.** Upstream keeps nothing that outlives a
`PangoLayout`, so a browser that measures a run and then paints it hands
the same bytes to HarfBuzz twice, and a table cell is shaped for
`min-content`, for `max-content` and again to lay out. `ns-shape-cache.c`
keeps the finished glyph string in a process-wide hash keyed on everything
`hb_shape` reads, and only for runs whose shaping cannot depend on the text
around them — which includes runs ending at a hyphenated break, and CJK,
where there is no whitespace to key off but ideographs, kana and Hangul
syllables neither join nor ligate. An item is cached a word at a time, and
**where it may be cut is the shaper's answer, not Unicode's**: a cut is only
taken where HarfBuzz clears the cluster of `UNSAFE_TO_CONCAT`, because a font
may kern the space against the word after it — Liberation Sans, which
fontconfig hands out for Arial, does — and a piece cut there would carry a
width belonging to whatever paragraph happened to be shaped first. An item
nothing may be cut in is cached whole instead. A full cache drops the entries
nothing has read since the last sweep rather than clearing outright.
`pango_context_get_metrics` is likewise cached per font description rather
than only for the context's own, bounded, and dropped when the fontmap
changes. `ns_pango_cache_trim` gives back everything nothing has read since
the last sweep, and `ns_pango_cache_clear` gives back the lot. Set
`NS_PANGO_SHAPE_CACHE=0` to disable all three caches, or `=verify` to serve
each run from the cache, shape it again, and warn on any difference;
`ns_pango_cache_get_skips` reports why runs were not cached.

**Every symbol is renamed** — `ns_pango_*`, `NsPango*`, `NS_PANGO_*`,
`NS_TYPE_PANGO_*`, and headers included as `<web-text-lib/...>`. GTK loads the system
Pango into the same process, and GObject aborts when a second library
registers a type name it already holds. `ns-rename.py` performs the whole
rewrite and is idempotent, so run it after merging upstream instead of
editing by hand. Engine code that must also build against stock Pango maps
the renamed spellings back through `src/ns_pango_names.h`, generated by
`scripts/gen-ns-pango-names.py`.

**CSS properties upstream cannot express.** `word-spacing` had no route
through Pango at all: letter spacing goes between every grapheme, so the
nearest a browser could get was an attribute per separator character, which
splits the paragraph into an item per word. `NS_PANGO_ATTR_WORD_SPACING`
and `ns_pango_glyph_item_word_space` add the space to the advance of each
word-separator character, at the seven characters CSS Text names and
nowhere else. Line height follows the CSS inline model: each run's ascent
and descent are rounded to whole pixels, the half-leading above the text is
floored the way Chrome splits it, and `ns_pango_layout_set_strut_line_height`
unites every line with the block's strut, so a line built only from a
smaller span still has the block's height. On macOS, Times, Helvetica and
Courier get 15% more ascent, as Chrome and Safari give them, and with
`line-height: normal` a fallback font also brings its own line gap.
`ns_pango_layout_run_get_css_extents` gives the same box for one run, for
lines the engine assembles itself around inline-blocks.

**Fixes for what a browser hits and a widget toolkit does not.** A synthesised
bold face was measured with HarfBuzz's unbolded advances and drawn with
FreeType's bolded ones, so `font-synthesis: weight` set too tight, worst in
CJK, where the glyphs already fill the em box. Letter spacing is added after
every character, the last one on a line included, as CSS and Chrome do;
upstream split it around each character and trimmed it at the line's ends. A
range with `allow_breaks=false` kept its break opportunities after en dashes,
soft hyphens, `|` and zero-width spaces, so a `white-space: nowrap` link such as
"Pale Moon 3.6.29–3.6.32" still wrapped; such a range now keeps only its
mandatory breaks.

**Concurrency the library now survives, though the browser does not yet use it.**
The browser calls into this library only from each renderer process's main loop —
its parallelism is processes, not threads — so these are latent wins rather
than wins today. The font metrics recursion guard was one process-wide flag,
so two threads laying out the same paragraph broke its lines differently.
`shape.c` kept one HarfBuzz buffer for the whole process behind a trylock, so
every thread but one allocated a buffer per run; each thread has its own now,
which is worth a few percent even single-threaded. The shape cache takes a
reader-writer lock, so warm lookups no longer serialise. On four cores, layout
throughput with the cache serving scales 3.2x where it scaled 2.4x.

**Backends and tooling a browser never links are gone**: Xft,
Win32/DirectWrite, CoreText, the deprecated `pango_ot_*` API, layout
serialization, FT2 rendering and its fontmap, the test suite, examples,
utilities, documentation and GObject-introspection. What remains is the
core text layer with the cairo and fontconfig/FreeType backends.

`BROWSER-COMPARISON.md` sets all of this against the equivalent code in Firefox
and Chrome — what each caches and how it bounds it, where the performance comes
from, and what each lets a page reach — and records what that comparison found
here.

Going forward, pango versions will simply be increasing triples, with
no particular significance to the parity of the minor version.
